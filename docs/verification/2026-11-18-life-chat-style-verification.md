# 聊天界面与首页入口检查

## 本轮完成标准

- 聊天沿用原「一句话记账」的米白背景、小团子头像、浅绿气泡、小票和底部输入栏。
- 首页的聊天入口进入事项标题行，有记录时不再单独占一行，没有记录时仍可进入。
- 原有三个业务入口和上下排列的悬浮入口可正常点击，例句只填入，首次同意和点击确认的要求保持。
- 在 375 和 320 像素宽的实际页面检查长文字、加载、失败、取消和查回，输入框不被挤出。
- 完成代码检查、小程序构建和包大小检查，不增加模型调用，不写入真实家庭资料。

## 改了什么

首页「一句话记事」位于第一个事项分组标题右侧，使用无底色的文字按钮。空列表时与「事项」标题同排。页面底部增加留白，最后的内容可以滚到悬浮按钮上方。

聊天每次回复前都显示小团子头像和「睦录」，开场例句收进气泡。确认卡直接使用原记账小票的票头、虚线和按钮；修改显示原值和新值，删除显示提醒，长备注用普通字号和字重。查账结论、可打开的原记录和保存结果分开显示，输入栏按原页方式避让导航和键盘。

最后确认的版本把金额修改前后并排显示，日期、地点、备注等字段加上浅绿图标。确认或地图选点按钮放在取消上方。用虚构资料在 320 和 375 像素宽的页面复查了样式和操作，95 组、992 项测试通过，扫码包也通过了构建与体积检查。

本机浏览器打开实际应用，用独立虚构资料检查。两种宽度的排版检查拦截对外网络，不调用真实模型或家庭服务。应用内浏览器连接失败，按可用方式改用本机浏览器；本轮没有重新进行微信模拟器或手机实测。

- 检查气泡、小票、输入区无横向溢出；输入栏位于可视窗口底部。
