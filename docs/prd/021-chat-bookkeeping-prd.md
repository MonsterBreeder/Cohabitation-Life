# PRD 021 睦录聊天记账

需求和小票草图已确认。本地页面和微信模拟器已验证，手机检查待完成。本文补充 [PRD 020](020-ai-bookkeeping-prd.md) 的页面交互。

## 用户怎么记

1. 从现有「一句话记账」入口进入，看到对话和底部输入框。第一次发送前，在聊天里说明本次输入和必要的类目、成员显示信息将用于模型处理。用户点「同意并发送」才发送。拒绝后可返回手动记账。
2. 输入「昨天午饭 50，打车 28」。睦录问「这两笔是谁付的？」时，直接回「都是我付的」。前面的描述和追问依次留在当前聊天。
3. 信息齐全后，在聊天里出现一张待确认卡片。逐笔显示金额、收支、用途、类目、具体日期和成员。明确提供了备注或餐段时也显示。说「打车改成 32」会更新原账目，卡片也有逐笔调整入口。
4. 点卡片里的「确认记账」才开始写入。对话里的「记吧」只提示使用卡片。带改动的回复先改草稿，再给用户核对。旧卡片和被撤回的卡片只供回看。
5. 每笔保存结果在聊天里显示。全部成功后，直接发送下一笔。遇到部分成功时，待核对项先查原回执，已经成功的账目可以打开查看。当前页还保有有效草稿且允许继续时，明确失败和未执行的项才可确认补存。想另记时先结束原批，原回执仍可查回。

## 页面设计

用睦录现有的奶油白、浅绿和深绿，聊天里用品牌小团子做头像。确认卡像一张小票，顶部显示合计和笔数，餐饮和出行分别配碗筷、小车图标。其他类目用通用标签图标，保留类目名。金额右对齐，回执用图标和文字区分「已记账」「待核对」等状态。输入区贴近底部，键盘弹出时仍能发送。读旧消息时，后到的结果不强行滚动页面。

首次打开时居中显示深绿色转圈和「正在加载账本记账页。」。整理、调整、保存和核对分别在相关消息或卡片后显示进度，保留已经显示的内容。一个操作只出现一处转圈，结束后在同一处显示结果或失败原因。失败提示说明下一步可以做什么。

## 数据与边界

新建账目的「一句话记多笔」入口与家庭邀请共用数据库开关。开关关闭、缺失或读取失败时，单人和双人家庭均隐藏入口，打开旧页面地址时提示返回手动记账。手动新增、编辑和共同账本照常使用。开关位置见[家庭邀请设置](004-invite-join-home-prd.md#首页转发与邀请开关)。

每批最多十笔文字描述的人民币收支。缺必要信息先问，支持原有收入、支出和共同账本规则。保存以实际回执为准，重复点击确认只处理一次。明确停止只停后续尚未开始的保存。普通退出清空未完成输入、聊天消息及草稿，已确认的保存按原规则处理。再进入只可查回允许保留的原保存状态。记账对话不写入个人长期记忆。

本轮改版范围为「一句话记账」页面和相关入口文案。正式发布、真实模型复验和正式账本写入各自另行确认。

## 验收

在睦录实际入口走通发送、补问、修改、确认、查看回执和直接记下一笔。用虚构账目检查确认前零写入、重复确认不重记、部分成功先查回、退出和切换家庭不恢复旧对话。微信开发者工具及手机分别检查键盘、窄屏、多笔卡片、滚动和加载。两端的检查结果分开记录。
