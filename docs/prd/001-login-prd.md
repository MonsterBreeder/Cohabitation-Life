# PRD 001：登录与身份确认

## 问题与目标

第一次打开“家里有事”的用户，需要先明确知道这个产品能为两个人做什么，再主动完成登录。登录过程要让用户感到温暖、可信和轻松，同时保证用户操作前不创建身份、不索取当前阶段不需要的信息。

## 产品要求

**页面与氛围**

- R1. 未登录用户进入小程序时，只显示登录页，不提前进入家庭或事项页面。
- R2. 页面采用温暖陪伴型风格，使用已经确认的情侣 Logo，并搭配少量柔和装饰，不另做大幅插画。
- R3. 页面使用项目视觉标准中的奶油色背景、薄荷绿主色和珊瑚色点缀，具体以 `docs/brand/visual-standard.md` 为准。
- R4. 页面显示产品名“家里有事”，主文案为“两个人的小事，一起记得”，辅助说明为“一起记住、认领和完成家里的小事”。

**登录操作**

- R5. 主按钮文字为“微信快捷登录”。
- R6. 登录按钮下方显示“已阅读并同意用户协议和隐私政策”的勾选项。当前开发阶段只展示文字，不提供查看入口；正式发布前必须补充正式正文和可查看入口。
- R7. 用户未勾选协议时点击登录，不发起登录，页面提示“请先阅读并同意用户协议和隐私政策”。
- R8. 用户主动点击登录且同意协议后，才开始识别或创建用户；点击前不创建用户资料。
- R9. 登录过程中按钮显示处理中状态，并阻止连续点击造成重复结果。
- R10. 第一版不获取手机号，也不强制获取微信昵称和头像。

**登录结果**

- R11. 从有效邀请进入的用户，登录成功后前往加入家庭确认页。
- R12. 已加入家庭的用户，登录成功后进入首页。
- R13. 尚未加入家庭且没有有效邀请的用户，登录成功后进入创建家庭引导页。
- R14. 登录失败时继续停留在登录页，不创建重复用户，并提供“重新登录”的明确入口；用户点击登录前离开页面时不创建用户。本方案不调用微信资料授权接口，因此没有平台“取消授权”弹窗。
- R15. 用户从邀请进入时，邀请信息需要保留到登录结束并再次确认；如果邀请已经失效、已被使用或家庭已满，显示原因并提示用户联系对方重新邀请，不自动进入创建家庭引导页。
- R16. 已经主动登录过且登录状态仍然有效的用户，再次打开小程序时不重复展示登录页，直接根据当前家庭状态前往对应页面。

## 验收标准

- 第一次打开时，用户能看到 Logo、产品名、主文案、辅助说明、登录按钮和协议勾选项。
- 未勾选协议时无法开始登录，并能看到清楚的提示。
- 点击登录前没有创建用户，登录成功后可以正确识别已有用户或创建新用户。
- 邀请用户、已有家庭用户和无家庭用户登录后，分别到达正确页面。
- 邀请在登录期间失效、被使用或家庭已满时，用户能看到明确原因，不会误入创建家庭流程。
- 登录中无法重复提交；登录失败后可以重新尝试，点击登录前离开不会创建用户。
- 已登录用户再次打开小程序时不需要重复登录。
- 整个登录流程不要求手机号、微信昵称或头像。

## 范围边界

- 本阶段只设计和实现登录页及登录后的去向判断。
- 本阶段暂不制作用户协议和隐私政策的正文页面，但这两项是正式发布前必须补齐的内容。
- 不包含手机号授权、游客模式、账号注销、个人资料编辑。
- 不在本阶段设计创建家庭、加入家庭和首页的页面内容，只保证登录后能够前往对应入口。
- 不新增独立登录方式，例如短信、邮箱或账号密码。

## 关键决定

- 采用温暖陪伴型页面：符合情侣共同生活的产品定位。
- 沿用现有情侣 Logo：保持品牌统一，也避免为首个页面扩大设计范围。
- 协议采用主动勾选：让用户在登录前清楚知道自己同意了什么。
- 第一版不获取手机号：当前建立小程序用户身份不需要手机号，减少首次使用阻力。

## 成功标准

- 用户无需解释即可理解产品用途，并能完成登录。
- 登录过程中没有重复创建、错误跳转或卡死在无反馈状态的情况。
- 页面视觉与现有品牌标准一致，且没有加入超出当前阶段的资料收集。
