# PRD 008：家庭共同流水账

## 问题与目标

PRD 005 ~ 007 把"家里的事"从"提醒清单"做成了"两个人共同维护的待办池"后，下一个被频繁提到的小事是钱：

- 出门买菜 50 元，月底两人坐下来对账时谁也记不清到底花了多少
- 想看"这个月餐饮 / 交通 / 居家分别花了多少"，得翻微信支付 / 支付宝账单，但账单里夹杂外卖、网购，跟家里的"共同开销"不是一回事
- 两个人分开记，最后汇总时互相怀疑数字记错，反而变成"算账比不记账更累"

这期要补的就是**家庭共同流水账**：两人共享一本账，每笔都记金额 / 类目 / 谁付的 / 备注，月底能直接看到本月总账与按类目 / 按成员的分布。

> 明确**不做**的事：AA / 分摊 / 结算 / 已转 / 转账 / 预算提醒 / 定期账 / 多币种 / 多人家庭（>2 成员）/ 跟"事项"模块的自动联动。

PRD 005 共同事项是"单笔 + 列表"就上线，PRD 006 加了编辑和多人评论，PRD 007 加了软删除。**PRD 008 沿用同一条"小步快跑"路线**：MVP 只做"记一笔 + 看 + 统计"，绝对不做 AA 那一套（那是另一款产品）。本 PRD 末尾的"不做清单"逐条列了暂不做的功能，避免后续被"顺手做了"。

## 核心规则

1. **单一共同模式**：账本在家庭级别只存在一种模式（不像 PRD 005 共同事项那样有"完整"和"简化"两种）；任何家庭成员打开账本看到完全一样的列表。
2. **双方都能记录 / 编辑 / 删除自己的账**：A 记的账只能 A 编辑 / 删除，B 不能动；这是"我对自己记账内容负责"，跟 PRD 005 共同事项的"任何成员都能完成 / 放弃"形成对照（事项是协作完成 / 放弃，账目是各自的记录）。
3. **双方都能看到全部**：A 记的账 B 也能看到完整字段（含金额 / 类目 / 备注 / 凭证图）；不存在"私密账目"或"仅付款人可见"。**新加入家庭的成员也能看到全部历史账目**（R6）——这是"家庭账本"的核心语义，不为隐私做可见性裁剪。
4. **不计算 AA / 不计算谁欠谁**：账本不计算"理论应付 vs 实际付款"的差额；只展示"谁付了什么"。这是 MVP 边界。如果后续要做 AA，单独开新 PRD。
5. **金额永远以"分"为单位**：数据库存 `number` 类型的整数（`amountCents`），展示时 `formatYuan(amountCents / 100)`；输入时按"元"输入但保存为分。**永远不做浮点运算**。
6. **类目是家庭级共享**：家庭创建时初始化 8 个固定类目（餐饮 / 交通 / 居家 / 娱乐 / 医疗 / 服饰 / 教育 / 其他）；任何成员都可以"添加自定义类目"或"隐藏"已有类目（隐藏只影响自己看到的列表，不影响其他人）。类目没有"删除"操作（避免历史账目引用不存在的类目）。
7. **支出 / 收入两种类型**：收入指"入账的钱"（报销 / 红包 / 工资的一部分），跟"支出"对称；MVP 不做"转账"独立类型（A 转给 B 一笔钱用"收入"+"支出"两笔记会更啰嗦，但语义清晰；如果后续要做"转账"再开新 PRD）。
8. **凭证图（拍照记账）**：记一笔账时可选附加一张照片（发票 / 小票 / 截图），存到云存储的 `receipts/{householdId}/{entryId}.jpg`；列表 / 详情页用缩略图展示，点击放大查看原图。
9. **拍照只用作证据，不做 OCR**：MVP 阶段不试图识别照片里的金额 / 日期 / 商家（OCR 准确率有限、调试成本高、用户也要手动核对）；用户拍完照仍需手填金额 / 类目 / 时间。**拍照"只是把纸面凭据数字化"**，不是"扫码记账"。
10. **软删除 + 30 天清理**：跟 PRD 007 事项软删除完全一致的语义；删除后列表立刻消失（双方都看不到），30 天后由 `cleanup-deleted-ledger-entries` 定时任务物理清理。
11. **不联动事项模块**：账目不引用 `taskId`，"买菜"事项完成时不会自动生成账目；用户在记账页里自己手动记。理由：让两个模块解耦，未来一个改另一个不受影响。
12. **新成员看到全部历史账目**：B 加入 A 已存在 3 个月的家庭后，B 打开账本看到 A 记的全部 3 个月历史账目。这是"家庭账本"的核心语义，不做"加入日之前不可见"这类边界裁剪。**新成员不能编辑 / 删除 A 记的旧账**（R2）；A 仍然是那些账的"记账人"。

## 概念与字段

### 账目（LedgerEntry）

| 字段 | 类型 | 必填 | 限制 | 备注 |
| --- | --- | --- | --- | --- |
| `_id` | string | 是 | 云端生成 | 内部键，不暴露给前端 |
| `householdId` | string | 是 | 家庭内部键 | 索引 + RLS 范围 |
| `payerId` | string | 是 | 必须是当前家庭成员 key | 谁付的钱；不引用外部 user 编号 |
| `type` | `'expense' \| 'income'` | 是 | 二选一 | 支出 / 收入 |
| `amountCents` | number (int) | 是 | 1 ~ 999,999,999（≤ ¥9,999,999.99）；整数 | 单位是分；负数 / 0 / 浮点全部拒绝 |
| `categoryId` | string | 是 | 必须属于该家庭类目集 | 引用 LedgerCategory |
| `note` | string | 否 | 0 ~ 100 字 | 首尾去空；不填则存空串 |
| `occurredAt` | Date | 是 | 不可晚于"今天 + 1 天"；不可早于 2020-01-01 | 账目发生时间，可与 createdAt 不同（补记） |
| `receiptMediaId` | string \| null | 否 | 云存储 fileID | 拍照记账的可选凭证图 |
| `createdAt` | Date | 是 | 云端时间 | 记录创建时间 |
| `updatedAt` | Date | 是 | 云端时间 | 最后修改时间；编辑后必更新 |
| `deletedAt` | Date \| null | 否 | 软删除标记 | 30 天后物理清理 |
| `deletedBy` | string \| null | 否 | 删除者内部键 | 软删除时记录 |

> 字段命名约定沿用 PRD 005 / 006 / 007：内部键加 `Id` 后缀（`householdId` / `payerId` / `categoryId`），不暴露给前端；展示字段（`type` / `note` / `amountCents`）直接给前端。
> 金额字段 `amountCents` 用 `number` 但语义上永远是整数；前端做 `Math.round` 兜底，云端在写入前做 `Number.isInteger` 校验（拒绝小数和负数）。

### 类目（LedgerCategory）

| 字段 | 类型 | 必填 | 限制 | 备注 |
| --- | --- | --- | --- | --- |
| `_id` | string | 是 | 云端生成 | 内部键 |
| `householdId` | string | 是 | 家庭内部键 | 每个家庭有独立类目集 |
| `key` | string | 是 | 8 字符以内；同家庭唯一 | 英文小写 + 连字符，如 `dining` / `transport` |
| `name` | string | 是 | 2 ~ 8 个汉字 | 展示名 |
| `iconKey` | string | 是 | 必须是预设图标池里的 key | MVP 阶段只允许用预设图标（不开放自定义图标） |
| `colorKey` | string | 是 | 必须是预设颜色池里的 key | 同上 |
| `isCustom` | boolean | 是 | true = 用户添加，false = 系统预设 | 用于列表角标 |
| `isHiddenBy` | string[] | 否 | 数组，存用户 key | "对我隐藏"的成员列表；不删除类目 |
| `sortOrder` | number | 是 | 0 ~ 999 | 类目展示顺序 |
| `createdAt` | Date | 是 | 云端时间 | |
| `deletedAt` | Date \| null | 否 | 软删除标记 | 类目删除时仅当无引用账目才允许 |

**8 个固定类目（系统预设）**：

| key | name | iconKey | colorKey | sortOrder |
| --- | --- | --- | --- | --- |
| `dining` | 餐饮 | `fork-spoon` | `amber` | 0 |
| `transport` | 交通 | `car` | `blue` | 1 |
| `home` | 居家 | `house` | `mint` | 2 |
| `entertain` | 娱乐 | `gamepad` | `coral` | 3 |
| `medical` | 医疗 | `first-aid` | `red` | 4 |
| `clothing` | 服饰 | `shopping-bag` | `purple` | 5 |
| `education` | 教育 | `book` | `teal` | 6 |
| `other` | 其他 | `tag` | `gray` | 7 |

> 类目字段命名沿用 `key` / `name` 而不是 `id` / `label` 是为了和 PRD 005 共同事项的 `type` 字段风格保持一致；前端展示时统一用 `categoryName` 字段（响应中 `category: { id, name, iconKey, colorKey }`）。
> 类目的 `isHiddenBy` 用数组而不是单个 `isHidden` 布尔：未来支持多人家庭时不会大改 schema（虽然 MVP 限定双成员）。

### 收据图（ReceiptMedia）

凭证图不是单独的"对象"，只是云存储里的一个文件 + 账目上的 `receiptMediaId` 引用：

- 上传：`wx.cloud.uploadFile({ cloudPath: 'receipts/{householdId}/{entryId}.jpg', filePath })`
- 访问：`wx.cloud.getTempFileURL({ fileList: [mediaId] })` 获取临时 URL（2 小时有效）
- 删除：账目硬删除 30 天后连带 `wx.cloud.deleteFile({ fileList: [mediaId] })`
- 大小限制：≤ 5 MB（前端用 `uni.chooseImage` 选图后压缩到 1080p 再上传）
- 格式限制：jpg / png / heic（云端转存为 jpg 节省存储）

## 数据可见性与权限矩阵

| 操作 | 自己记的账 | 对方记的账 | 备注 |
| --- | --- | --- | --- |
| 查看列表 | ✓ | ✓ | 双方看全部 |
| 查看详情 | ✓ | ✓ | 全部字段 |
| 编辑 | ✓ | ✗ | 只创建者可改 |
| 删除（软删） | ✓ | ✗ | 只创建者可删 |
| 撤销删除 | ✓ | ✓ | 任何成员可恢复被软删的账（30 天内）；防止误删 |
| 标记（已转 / 已付） | n/a | n/a | MVP 没有这概念 |

类目相关：

| 操作 | 系统预设 | 自定义类目 | 备注 |
| --- | --- | --- | --- |
| 添加 | ✗ | ✓ | 任何成员可加自定义 |
| 重命名 | ✗ | ✓ | 只能改自己创建后没人引用的自定义类目 |
| 隐藏（对自己） | ✓ | ✓ | `isHiddenBy` 数组加自己 key |
| 取消隐藏 | ✓ | ✓ | `isHiddenBy` 数组移除自己 key |
| 删除 | ✗ | △ | 仅当无账目引用时可删 |

## 用户流程

### 1. 从底部 tab 进入家庭账本

```
底部 tab（首页 / 账本 / 我的）
  └── 点 "账本" tab → reLaunch `/pages/ledger/index`
```

账本 tab 是底部第二个 tab（首页 / 账本 / 我的），Wot UI `wd-tabbar` 实现，icon 用 `wallet`。
PRD 008 早期版本曾在首页放"家庭账本"入口卡，后改为独立 tab（避免和首页事项区互相挤占视觉空间）。

### 2. 账本首页

```
ledger-home
  ├── 月度概览
  │    ├── 本月支出 ¥X
  │    ├── 本月收入 ¥Y
  │    ├── 净支出 ¥X - Y
  │    └── 类目分布条
  ├── 筛选条
  │    ├── 成员筛选：全部 / 我 / 对方
  │    ├── 月份切换：< 2026-08 >
  │    └── 类目筛选（chip 形式，多选）
  ├── 账目列表
  │    ├── 按日期分组（今天 / 昨天 / YYYY-MM-DD）
  │    └── 每条：付款人头像 + 类目 + 备注 + 金额（支出红 / 收入绿）+ 凭证缩略图
  └── 浮动操作按钮 "记一笔"（右下角）
```

### 3. 记一笔

```
ledger-add
  ├── 顶部 tab：支出 / 收入
  ├── 金额输入（带 ¥ 前缀；整数键盘；自动除以 100 存分）
  ├── 类目选择（8 个固定 + 自定义 chip 形式）
  ├── 付款人选择（默认 = 当前用户；可切换为对方）
  ├── 备注（可选，0-100 字）
  ├── 发生时间（默认今天；可往前选 7 天 / 30 天；不可选未来）
  ├── 凭证图（可选；点击触发 chooseImage）
  └── 底部 "保存" 按钮
```

### 4. 账目详情

```
ledger-detail
  ├── 类目 + 金额（大字号顶部）
  ├── 付款人头像 + 昵称
  ├── 备注（如有）
  ├── 发生时间 + 创建时间 + 最后修改时间
  ├── 凭证图（点击放大查看原图）
  └── 操作区
       ├── "编辑"（仅自己记的账）
       ├── "删除"（仅自己记的账；二次确认）
       └── "返回"
```

### 5. 列表筛选 / 统计

```
ledger-home 的筛选条
  ├── 成员筛选：切换 = 实时重新查询；显示"全部"时无成员过滤
  ├── 月份切换：左右箭头 + 点击月份弹出"选择月份"弹窗（仅显示有账目的月份）
  └── 类目筛选：点击类目 chip 切换选中状态；多选 = OR 关系

统计切换：首页右上角"统计"图标 → 跳转 ledger-stats
  ├── 按类目饼图（金额占比）
  ├── 按成员柱状图（A / B 各自付了多少）
  └── 月度对比（本月 vs 上月）
```

## 状态机

账目是简单的"非删除 ↔ 软删除"两态，**没有"已转"或"已结算"概念**（R4）：

```
       创建
        │
        ▼
   ┌─────────┐
   │  active  │ ◀─── 编辑（更新字段，updatedAt +1）
   │ (默认态) │
   └────┬─────┘
        │ 删除（仅创建者）
        ▼
   ┌─────────┐
   │deletedAt│  30 天后由 cleanup-deleted-ledger-entries 物理清理
   │ (软删除) │
   └────┬─────┘
        │ 30 天内可恢复
        ▼
   active
```

## 边缘场景

| 场景 | 处理 |
| --- | --- |
| 记一笔但家庭只有自己（单成员） | 允许；付款人 = 自己；不显示"切换付款人"按钮；统计页只显示自己一列 |
| 新成员加入有 3 个月历史的家庭 | 看到全部 3 个月历史；可编辑 / 删除自己记的；不能编辑 / 删除前任的旧账 |
| 删除了某成员后 | 该成员记的账在 `payer` 字段上保留旧 key；列表显示"（已离开）"灰态 |
| 类目被引用（至少 1 笔账） | 不允许删除；提示"该类目下还有 N 笔账，请先修改或删除账目" |
| 凭证图上传失败 | 提示重试；账目保存不受影响（`receiptMediaId` 留 null） |
| 凭证图超过 5 MB | 客户端 chooseImage 阶段就拒绝；提示"图片过大，请重新选择" |
| 时间晚于今天 +1 天（手机时区错乱） | 客户端先校验；云端再次校验；拒绝 |
| 时间早于 2020-01-01 | 客户端先校验；云端再次校验；拒绝 |
| 金额 = 0 | 客户端先校验（禁用保存）；云端拒绝（amountCents >= 1） |
| 金额 = 负数 | 同上 |
| 金额 = 浮点（如 12.5 元 → 1250 分） | 客户端四舍五入；云端 `Number.isInteger` 拒绝小数 |
| 双方同时编辑同一笔账 | 没有 editVersion 乐观锁（R 决定不做）；后写覆盖前写（last-write-wins）；金额 / 备注差异由用户自行协调 |
| 凭证图所属账目被删除 | 30 天后账目物理删除时连带删除云存储文件 |
| 收入 / 支出类型切换 | MVP 不允许（保存后类型不能改）；如需改变类型，先删除再记新的一笔 |
| 备注里有敏感信息（如密码） | MVP 不做脱敏；用户自己注意；后续可加"备注仅自己可见"扩展 |

## 不做清单（明确排除）

为了让 MVP 边界清晰，下面这些功能**本期不做**，等下一个或几个 PRD 再决定：

1. ❌ **AA / 分摊 / 结算 / 已转** — 这是另一款产品（"AA 记账"），需要单独的 PRD
2. ❌ **转账独立类型** — 收入 + 支出两条线已经覆盖"我给 A 转了一笔"的场景
3. ❌ **预算 / 提醒**（"本月餐饮预算 1000"）— 提醒类功能 PRD 009 家庭汇总 / 通知可能涉及
4. ❌ **定期账**（"每月 1 号自动记一笔房租"）— 需要定时任务调度，与 PRD 005 共同事项的状态机复杂度相当
5. ❌ **OCR 自动识别**（拍照后自动填金额 / 类目）— 准确率 + 调试成本
6. ❌ **多币种** — MVP 仅 ¥；后续要加 USD / HKD 再开 PRD
7. ❌ **多人家庭（>2 成员）** — 与 PRD 005 共同事项"2 成员硬约束"保持一致
8. ❌ **与"事项"模块联动** — "买菜事项完成 → 自动生成账目"是诱人的功能，但会让两个模块的数据模型互相引用；R3 决定 MVP 完全解耦
9. ❌ **私密账目 / 仅自己可见** — R3 决定"双方都看全部"
10. ❌ **类目自定义图标 / 自定义颜色** — 限制为预设池，避免设计失控
11. ❌ **备注脱敏 / 加密** — 备注本身就是非敏感文本，不做加密
12. ❌ **乐观锁**（`editVersion`） — R 决定 MVP 用 last-write-wins；并发编辑的差异由用户协调
13. ❌ **Webhook / 推送通知**（"对方记了一笔账，实时推送给我"）— 这是 PRD 009 的范围
14. ❌ **导出 CSV / Excel** — 用户社区功能，可后期加
15. ❌ **搜索功能**（按关键字搜备注）— MVP 列表量级（一般家庭每月 < 100 笔）下不需要
16. ❌ **年度报告**（"2026 年家庭共支出 X 元"）— 属于统计扩展，跟"汇总 / 通知"是同一个 PRD 范围

部署到测试环境后，按以下 8 条路径逐一验证（每条都用两台手机 A / B）：

## 实施依赖

实施时需要先准备好：

1. **数据库新集合**：
   - `ledgerEntries`（账目）
   - `ledgerCategories`（类目，家庭级共享）
2. **云存储目录**：`receipts/{householdId}/`
3. **新云函数** `ledger`：
   - `initCategories`（家庭创建时调用，初始化 8 个固定类目）
   - `addEntry`（创建账目）
   - `updateEntry`（编辑账目；仅创建者）
   - `deleteEntry`（软删除）
   - `restoreEntry`（恢复软删的账）
   - `listEntries`（按 household + 筛选）
   - `getEntry`（详情）
   - `addCategory`（自定义类目）
   - `updateCategory`（重命名 / 切换隐藏）
   - `removeCategory`（仅当无引用）
   - `getStats`（按月统计 + 按类目 + 按成员）
4. **新定时任务** `cleanup-deleted-ledger-entries`（每日 03:00 跑）
5. **新前端包** `subpackages/ledger/`：
   - `ledger-home`（账本首页 + 列表 + 筛选）
   - `ledger-add`（记一笔）
   - `ledger-detail`（详情 + 编辑 + 删除）
   - `ledger-stats`（统计）
   - `ledger-category-manager`（类目管理）
   - 共用组件：`LedgerEntryItem.vue` / `CategoryPicker.vue` / `MemberFilter.vue` / `ReceiptThumb.vue`
6. **新 Pinia store** `ledger.ts`（账目列表 + 类目 + 筛选状态 + 统计缓存）
7. **首页改动**：`pages/index/index.vue` 增加"家庭账本"入口卡

## 风险与开放问题

1. **凭证图存储成本**：每个家庭一年约 100-300 张凭证图 × 平均 500 KB = 50-150 MB / 家庭 / 年。**需要决定**：是否限制凭证图总张数（如 ≤ 500 / 家庭）或者总大小（如 ≤ 200 MB / 家庭）？MVP 不做配额，但需要监控云存储用量。
2. **类目预设图标的视觉统一**：8 个固定类目 + 用户自定义的图标 / 颜色必须跟 `docs/brand/visual-standard.md` 的色板对齐；自定义类目锁在预设池避免设计失控是 MVP 决策。
3. **拍照权限**：iOS / Android 拍照权限弹窗体验差异；MVP 不做权限拒绝的引导页（直接用 `uni.chooseImage` 的内置弹窗）。
4. **收入 / 支出的 UI 区分**：金额颜色（红 / 绿）是否符合用户预期？建议在 PRD 评审时给视觉稿。
5. **统计页的图表库选择**：要不要引第三方图表库（uCharts / F2）？MVP 阶段用纯 CSS 画（饼图 / 柱状图）；后续可加。
6. **记账入口在首页的位置**：现在是"家庭"+"事项"+"我的"3 卡之间插 1 卡；如果未来加"家庭汇总"是第 5 卡，"我的"就要换位置——这是一次性的 UI 调整，无所谓。
7. **凭证图云存储删除的幂等性**：30 天物理清理时如果云存储文件已经不存在，要优雅处理（`wx.cloud.deleteFile` 对不存在的 fileID 是静默 no-op，但要确认）。
