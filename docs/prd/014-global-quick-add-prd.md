# PRD 014 全局快速新增

状态：已确认

## 问题与目标

当前右下角加号会随所在页面改变用途：用户想记账时，必须先切换到账本；想记录事项或足迹时，也要先找到对应页面。高频记录因此多了一次导航，且同一个加号在不同位置含义不同。

本需求把加号统一为全局快速新增入口。用户在浏览家庭内容时，可以直接选择记账、记事项或记足迹，不必先切换栏目。

## 需求

**入口与展开方式**

- R1. 已有家庭且当前页面不是填写、编辑或管理页面时，右下角显示统一的加号入口。
- R2. 点击加号后，在加号上方向上展开“记账”“记事项”“记足迹”三个小按钮，每个按钮同时显示容易识别的图标和文字。
- R3. 三个入口的位置始终固定：离加号最近的是“记账”，其次是“记事项”，最上面是“记足迹”，不随当前页面改变。
- R4. 菜单展开后，加号变为关闭按钮；再次点击可收起菜单。
- R5. 菜单展开和收起应在 300 毫秒内完成；选择任一入口后直接进入填写页面，不等待收起动画结束。

**遮罩与操作保护**

- R6. 菜单展开时显示半透明遮罩，覆盖当前页面内容和底部栏目，阻止用户误触遮罩后的按钮或切换栏目。
- R7. 加号、三个新增入口及对应文字位于遮罩上方，保持清晰且可点击。
- R8. 点击遮罩空白处、关闭按钮或任一新增入口后，菜单立即收起。
- R9. 快速连续点击加号或新增入口时，不得重复打开页面，也不得出现多个遮罩或菜单。
- R10. 在支持拦截页面返回的平台，菜单展开时执行返回操作应先收起菜单；微信小程序左上角系统返回不支持拦截，点击后允许直接离开当前页面，页面离开时菜单状态必须随之清除。
- R11. 当前页面已有弹窗、日期选择器等浮层时，快速新增入口暂时隐藏，避免多个操作层互相遮挡。
- R12. 三个小按钮及文字在窄屏上不得被截断或超出屏幕，按钮的可点击范围应适合手指操作。

**显示范围**

- R13. 现阶段仅在以下查看页面显示快速新增入口：首页、账本、足迹、“我的”、事项详情、历史事项、账目详情、账本统计、问账本、足迹详情和邀请状态。
- R14. 以下页面不显示快速新增入口：登录、创建家庭、加入家庭、填写或编辑事项、填写或编辑账目、填写或编辑足迹、编辑个人资料、编辑家庭资料、裁剪头像、成员管理和账本类目管理。
- R15. 家庭资料仍在确认、读取失败或用户尚未拥有家庭时，不显示快速新增入口。

**进入与返回**

- R16. 选择“记账”“记事项”或“记足迹”后，直接进入现有的对应填写页面，不新增另一套填写流程。
- R17. 保存成功后回到发起操作的原页面，并给出与所选动作一致的成功提示；原页面保持原有浏览位置和筛选状态，如果原页面展示了刚新增的同类内容，应同时更新显示。
- R18. 用户从填写页面返回但未保存时，仍回到原页面，不产生任何记录。
- R19. 如果进入填写页面失败，应留在原页面并给出明确提示，用户可以再次尝试。

## 成功标准

- 用户在任一允许显示快速新增入口的页面，最多点击两次即可开始记账、记事项或记足迹。
- 用户无需先切换到对应栏目，三种新增功能的入口位置和名称在所有页面保持一致。
- 展开菜单后，遮罩后的页面内容和底部栏目不能被误触。
- 保存或放弃后能回到发起操作的页面，不会被强制带到其他栏目。
- 加载、无家庭、填写编辑、页面浮层、页面返回和快速连点等情况下，不出现重复页面、遮挡冲突、残留菜单或错误记录。

## 范围边界

- 本需求只统一三个现有新增能力的入口，不改变事项、账目和足迹各自的填写字段、保存规则与数据权限。
- 本需求不新增第四种记录类型，也不提供自定义入口、入口排序或“记住上次选择”。
- 本需求不在填写、编辑和管理页面叠加快速新增入口。
- 本需求不改变底部四个栏目及其原有用途。

## 已确认决定

- 使用加号旁展开三个小按钮，而不是底部选择框或独立的快速新增页面。
- 展开时增加遮罩，避免误触背景内容。
- “记账”离加号最近，因为它是使用频率最高的动作。
- 入口顺序在所有页面固定，避免用户反复辨认。
- 保存后回到发起操作的页面，保持用户原来的浏览位置。
- 浏览页面显示，填写、编辑和管理页面隐藏。
- 接受微信小程序的系统返回限制：点左上角返回时直接离开当前页面，不为此改造全站顶部栏。

## 前提

- 事项、账目和足迹的现有填写页面继续可用。
- 三种记录都属于当前家庭；没有家庭时不提供快速新增入口。

本 PRD 已确认，下一步可据此制定实施计划，再进入开发。
