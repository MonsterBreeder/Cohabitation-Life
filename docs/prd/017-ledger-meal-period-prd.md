# PRD 017：餐饮账目增加早午晚餐选项

状态：已确认

## 问题与目标

现在记录餐饮支出时，只能选择“餐饮”类目。同一天有多笔餐饮消费时，用户只能依赖备注判断是哪一餐，不够直观。

本需求在选择系统自带的“餐饮”类目后，增加“早餐 / 午餐 / 晚餐”三个餐次选项。新建餐饮账目时，根据当前时间自动选中一个餐次，用户可以修改；保存后，双方都能在账目列表和详情中看到餐次。

目标是在不增加明显记账负担的情况下，让餐饮账目更容易识别。

## 核心规则

- R1. 只有选择系统自带的“餐饮”类目时，才显示早餐、午餐、晚餐选项。
- R2. 用户自己创建一个同名为“餐饮”的类目时，不显示餐次选项。
- R3. 新建餐饮账目时，根据设备当前本地时间自动选中餐次：
  - 00:00–10:59：早餐
  - 11:00–15:59：午餐
  - 16:00–23:59：晚餐
- R4. 自动选中后，用户可以在保存前改成另外一个餐次。
- R5. 用户修改金额、日期、付款人、备注或凭证时，不得覆盖已经手动选择的餐次。
- R6. 用户从餐饮切换到其他类目时，餐次被清空并隐藏；之后再次主动选择餐饮时，根据当时的本地时间重新自动选中。
- R7. 新增和编辑餐饮账目时，餐次都随账目保存，并在家庭双方之间共同可见。
- R8. 账目列表将餐次显示在类目后，例如“餐饮 · 早餐”；账目详情单独显示“餐次：早餐”。
- R9. 编辑一条已有餐次的账目时，必须准确回显原来的餐次，用户可以修改。
- R10. 历史餐饮账目没有餐次时，列表和详情不显示餐次；打开编辑页也不自动补写当前餐次。
- R11. 编辑历史餐饮账目时，可以只修改其他内容并继续保留“没有餐次”的状态；如果用户主动选择了餐次，则保存新选择。
- R12. 餐次只允许早餐、午餐、晚餐或空值，非餐饮账目不能保留餐次。
- R13. 旧版本仍可正常新增和编辑账目，不得因为没有餐次而失败；旧版本编辑一条已经有餐次的账目时，也不能把原餐次误删。
- R14. 餐次沿用现有账目权限：双方都能看到，只有账目创建者能编辑或删除。

## 用户流程

### 新建餐饮账目

```text
打开“记一笔”
  → 选择系统“餐饮”类目
  → 页面显示早餐 / 午餐 / 晚餐
  → 根据当前时间自动选中一个餐次
  → 用户可保持默认值或手动修改
  → 保存账目
  → 列表和详情显示最终餐次
```

餐次区域放在类目下方、付款人上方。三个选项使用清楚的文字按钮，不只依赖颜色或图标表达。

### 切换类目

```text
已选择餐饮和餐次
  → 切换到交通等其他类目
  → 餐次立即清空并隐藏
  → 再次主动选择餐饮
  → 按再次选择时的当前时间重新选中餐次
```

### 编辑账目

```text
打开已有餐次的餐饮账目
  → 编辑页回显原餐次
  → 用户可修改并保存

打开没有餐次的历史餐饮账目
  → 编辑页保持未选择
  → 只改其他内容时，餐次仍为空
  → 用户主动选择餐次后，才保存新餐次
```

## 数据规则

账目新增一个可为空的“餐次”字段：

| 页面显示 | 保存值 | 使用范围 |
| --- | --- | --- |
| 早餐 | `breakfast` | 系统餐饮类目 |
| 午餐 | `lunch` | 系统餐饮类目 |
| 晚餐 | `dinner` | 系统餐饮类目 |
| 不显示 | 空值 | 历史账目或非餐饮账目 |

历史账目不做批量补写。现有账目只可靠记录了日期，不能根据历史时间推断真实餐次；错误补写比保持空值更容易误导用户。

## 边缘场景

- 当前时间正好为 11:00 时，默认午餐；正好为 16:00 时，默认晚餐。
- 用户手动修改餐次后，再修改其他记账字段，餐次保持用户选择。
- 自定义类目即使也叫“餐饮”，仍按普通类目处理。
- 历史餐饮账目没有餐次时，不显示“未分类”等新文案，避免给旧数据增加不存在的含义。
- 双方看到的餐次必须一致，不能只保存在当前设备。
- 网络失败或保存失败时，继续沿用现有记账错误反馈和重复点击保护，不新增半保存状态。

## 成功标准

- 选择系统餐饮类目后，三个餐次选项正确出现并根据当前时间自动选中。
- 用户可以修改自动选择，保存后列表、详情和再次编辑显示一致。
- 切换到非餐饮类目后不会保存餐次。
- 已有餐次的账目编辑后不会丢失餐次。
- 没有餐次的历史账目可以正常查看和编辑，不会被自动补写。
- 自定义同名类目不会错误出现餐次选项。
- 家庭双方看到相同餐次，原有编辑和删除权限不变。
- 旧版本记账流程继续可用，统计、筛选、凭证、删除恢复和“问账本”不受影响。

## 验收示例

- AE1. 10:59 新建餐饮账目，默认选中早餐；用户改成午餐并保存后，列表显示“餐饮 · 午餐”。
- AE2. 11:00 新建餐饮账目，默认选中午餐。
- AE3. 16:00 新建餐饮账目，默认选中晚餐。
- AE4. 选择餐饮后改为交通，餐次区域消失，保存后的交通账目没有餐次。
- AE5. 用户创建一个名为“餐饮”的自定义类目，选择后不出现餐次选项。
- AE6. 编辑一条“餐饮 · 早餐”的账目，只改金额并保存，餐次仍是早餐。
- AE7. 编辑一条没有餐次的历史餐饮账目，只改备注并保存，列表和详情仍不显示餐次。
- AE8. A 保存一条晚餐账目，B 能看到“餐饮 · 晚餐”，但不能编辑或删除 A 的账目。
- AE9. 旧版本编辑一条已有午餐标记的账目时，没有传餐次也不会导致午餐标记丢失。

## 范围边界

- 本次不增加夜宵、加餐、下午茶等更多餐次；需要时仍可写在备注中。
- 本次不增加按餐次筛选、按餐次统计或首页餐次汇总。
- 本次不让“问账本”理解或查询餐次。
- 本次不批量修改历史账目，也不根据账目日期猜测餐次。
- 本次不改变类目管理、金额规则、付款人规则、凭证、软删除或家庭权限。

## 确认项

请确认以下产品规则后再开始开发：

1. 自动时段采用“早餐到 10:59、午餐 11:00–15:59、晚餐从 16:00 开始”。
2. 旧餐饮账目不自动补餐次，编辑时也保持原样。
3. 餐次会显示在账目列表、详情和编辑页，但本轮不进入筛选、统计或“问账本”。
