# PRD 018：睦录温馨生活视觉体系

状态：已确认

## 问题与目标

睦录现有页面已经具备统一的奶油白、薄荷绿和蜜桃珊瑚配色，但大量内容都由白色卡片、普通线性图标和文字组成。页面清楚可用，却缺少能够让人联想到“两个人共同生活”的独特视觉语言。

本次改造不更换主题色，也不增加新的业务功能。目标是在不减少首页现有信息、不降低事项和账本列表可读性的前提下，通过生活物件图标、小场景插画、真实成员头像和克制的反馈，让小程序更温馨，并形成能够持续扩展的睦录视觉语言。

## 核心视觉规则

- R1. 保留现有奶油白、薄荷绿、深薄荷绿和少量蜜桃珊瑚，不增加新的主色。
- R2. 新增图标和小插画统一采用圆润线稿与少量平面色块，整体年轻、温暖，但不做成儿童插画。
- R3. “两个人”的表达只用于家庭、共同事项、共同足迹等重点场景；编辑、删除、筛选等普通操作继续使用单个清晰图标。
- R4. 成对生活物件固定遵循“两个略有差异的物件并排，加一个共同小勾或两点光芒”的睦录印记，延续现有 Logo。可使用双杯、并排拖鞋、共同钥匙、双脚印等物件，但不能只堆放通用生活插画。
- R5. 底部“首页、账本、足迹、生活、我的”五个入口保留原含义和文字，统一重画为同一套圆润线稿；选中状态只增加少量品牌色块，不使用难以理解的新隐喻。
- R6. 主标题、金额、按钮和列表继续使用清楚易读的正常文字；手写感仅用于家庭封面、小标签或插画旁的短句。

## 首轮范围

- R7. 首轮改造首页、生活页、底部五个入口，以及当前确实存在的事项、账本和足迹空状态。
- R8. 账本和足迹首轮只修改空状态区域，不改其正常内容、筛选、列表和操作流程；我的、填写页和详情页不在首轮整体改造范围内。
- R9. 首轮样板必须使用同一套视觉规则，不能让首页、生活页、底部入口和空状态分别采用互不相关的画风。
- R10. 样板阶段额外检查高密度事项列表、高密度账目列表和含照片足迹三种压力场景，只验证视觉规则能否延展，不把对应页面的整体改造纳入首轮。

## 首页

- R11. 首页顶部使用紧凑的家庭封面，以家庭资料和成员头像为主要内容，双杯、共同钥匙等生活物件只作陪衬；家庭封面不得挤占过多首屏空间。
- R12. 双成员家庭显示两位真实成员头像。单成员家庭只显示当前成员头像，另一侧使用淡化占位和“等另一位加入”提示，并保留邀请入口；不得用虚构头像或品牌双人形象冒充已加入成员。
- R13. 成员头像缺失或加载失败时沿用现有默认头像；家庭名称或昵称较长时可以合理换行，不能挤压主要入口。
- R14. 首页内容顺序固定为：家庭封面、本月账本摘要、最近足迹摘要、事项列表、已完成事项入口。
- R15. 本月账本摘要继续显示本月支出和本月收入，不得退化成只有图标和标题的入口。
- R16. 最近足迹摘要继续显示地点数量、最近地点和日期；有封面照片时继续展示照片，没有照片或加载失败时使用同风格的品牌占位画面，并保留进入足迹页的入口。
- R17. 事项列表继续完整显示，并保留“优先处理、快到期、快没了、待处理”的现有分组；不得为了画面简洁只展示少量事项或隐藏后续内容。
- R18. 事项行保持紧凑清楚：生活物件图标位于左侧，事项名称为主要信息，成员头像、时间和状态为辅助信息；不为每一行增加大图片或厚重卡片。
- R19. 家庭封面、账本摘要、足迹摘要、事项行和已完成事项入口沿用现有点击目标与返回行为，不增加额外步骤，也不把不可用状态伪装成可点击。

## 生活页

- R20. 生活页采用“共同生活小架子”的整体构图，不继续使用整齐重复的普通卡片网格。
- R21. 页面固定分为页面说明、当前可用工具和即将开放工具三个层级。
- R22. 当前可用的徒步入口必须最醒目，使用成对徒步鞋、路线或相片等生活物件表达，并且整项可点击。
- R23. 尚未开放的入口放在下方并明确弱化，显示“即将开放”且不可点击，不能比徒步入口更抢眼。
- R24. 首轮仍以徒步为唯一主要入口；未来出现多个可用工具时，再单独确认排序规则。
- R25. 生活页继续是当前家庭私密使用的共同生活工具入口，不增加公开动态、陌生人内容或伴侣监督暗示。

## 空状态与反馈

- R26. 事项、账本和足迹的空状态使用两至三个生活物件组成的小场景，例如便签板与笔、小票夹与硬币、相片与双脚印；不为当前不存在空状态的生活页制作无效素材。
- R27. 空状态不使用完整房间或大幅户外插画；插画必须服务于下一步操作，标题、说明和主要按钮仍然清楚可见。
- R28. 首轮只在本次改造页面加入克制反馈：页面内容首次进入时轻微出现，按钮按下时轻微回弹；动画不得叠加，离开页面立即结束，操作失败时不显示成功反馈，结束后不改变内容布局。
- R29. 事项完成操作发生在首轮范围外的详情页，因此“完成盖章”反馈延期到详情页后续改造，不为增加动效改变现有事项流程。
- R30. 用户不依赖动画也能理解操作结果；无法确认系统减少动态效果偏好时，必须保留完整静态反馈。

## 状态与窄屏规则

- R31. 改造后的页面继续覆盖加载、失败、空数据、正常数据和重复点击保护，不能只设计理想状态。
- R32. 首页各区块继续独立呈现状态：家庭资料失败可以整页重试；账本摘要或足迹摘要失败时只影响对应区域并保留入口；事项加载失败时不隐藏已经成功显示的家庭、账本和足迹内容。
- R33. 重复点击继续沿用现有保护，不因新动效延长等待。
- R34. 窄屏或较大系统字体下，家庭名、地点和事项名称允许合理换行，辅助信息可以移动到下一行；金额和主要状态不得被装饰物遮挡或截断。
- R35. 主要点击区域必须易于触碰；装饰性图片不承担唯一含义，并且不被朗读成无意义内容。
- R36. 新增图片和图标必须控制数量与体积，优先使用小尺寸、可复用素材，不能为了温馨感明显拖慢首屏加载。

## 成功标准

- 用户进入首页时能首先感受到“这是我们共同生活的空间”，同时无需寻找就能看到本月账本、最近足迹和全部待办事项。
- 单成员家庭不会虚构第二位成员，仍能清楚看到邀请另一位加入的入口。
- 首页、生活页、底部入口和空状态看起来属于同一个品牌；成对物件能够让人联想到现有双人小团子 Logo。
- 增加温馨感后，金额、事项、时间、负责人、按钮和状态仍然清楚，列表浏览效率不低于改造前。
- 未开放的生活应用不会抢走徒步入口的注意力，也不会被误认为可以点击。
- 常见窄屏、较大系统字体、无照片、加载失败和空数据情况下，没有明显遮挡、溢出或无法操作的问题。
- 使用同一设备和同一组高密度数据，对照改造前后查找最紧急事项、确认负责人和时间、查看本月支出三个任务；不得出现明显误读，首屏可见信息不能因装饰大幅减少。
- 底部五个入口先用真实显示尺寸检查选中和未选中状态，用户能够结合文字快速辨认；首轮验收结束前保留现有图标作为回退方案。
- 页面检查、相关自动检查、微信小程序构建和包体积检查通过，并在微信开发者工具中完成首页、生活页、列表、空状态和轻微反馈的实际视觉确认。
- 首轮样板只有在用户确认页面气质正确、关键信息没有减少、列表查找没有明显变慢且真实设备显示正常后，才进入全站扩展；部分满足时先调整样板，未满足时回退，不长期保留无法继续扩展的两套视觉。

## 范围边界

- 本次不改变现有主题色和 Logo。
- 本次不新增账本、事项、足迹或生活应用的业务功能。
- 首轮不整体改造账本、足迹、我的及所有填写和详情页面；账本与足迹只允许修改已明确纳入的空状态区域和视觉压力测试稿。
- 不使用传统爱心、拥抱人物、婚礼元素、带烟囱房屋、排名、打卡或监督式视觉。
- 不使用大量通用生活照片、完整房间插画、复杂渐变、强阴影或持续动画。
- 不因为视觉调整减少首页现有账本、足迹和事项信息。

## 实施计划需要确认的内容

- 核对底部五个新图标和首轮生活物件在实际小尺寸下是否清楚，无法辨认的图形应在制作阶段替换。
- 明确首轮实际使用的图标、小场景和页面清单，避免把样板扩大成全站视觉重做。
- 依据首轮素材的实际大小确定最终压缩尺寸，并重新检查主包体积。
- 使用真实页面数据确认家庭封面的最大高度、事项列表密度和较大系统字体下的排版。

## 确认项

请确认以下产品规则后再开始实施计划：

1. 保留现有主题色，采用“圆润线稿＋少量色块”的画风。
2. 重点共同场景使用“两个略有差异的生活物件＋共同小勾”的睦录印记，普通操作继续使用单个清晰图标。
3. 首轮只改首页、生活页、底部入口，以及事项、账本和足迹空状态；不整体改造其他页面。
4. 首页继续完整显示本月账本、最近足迹和全部事项，顺序为家庭封面、账本、足迹、事项、已完成入口。
5. 单成员家庭显示真实头像和“等另一位加入”占位，不虚构第二位成员。
6. 生活页使用“共同生活小架子”，徒步为主要入口，未开放工具弱化并不可点击。
7. 手写感只用于装饰短句，空状态使用两至三个生活物件组成的小场景。
8. 首轮只加入页面首次出现和按钮回弹等轻微反馈，事项完成盖章留到详情页后续改造。
